01 · Overview

프로젝트 개요

PROJECT DESCRIPTION

MapleChat은 메이플스토리 Open API를 활용해 캐릭터·길드·유니온 정보를 조회하고 시각화하는 데스크탑 앱입니다. 캐릭터 이름 하나로 장비·스탯·유니온 배치까지 한 화면에서 확인할 수 있습니다. Spring Boot REST API가 Nexon Open API의 프록시 역할을 하고, React + Electron 프론트엔드가 데이터를 시각화합니다.

05 · Challenges

기술적 도전과 해결

01

Nexon API 2-step 구조 — OCID 인메모리 캐시 (팀원 구현)

넥슨 API는 캐릭터 이름으로 직접 조회가 불가능하고, 먼저 이름으로 OCID를 받아 이후 모든 요청에 사용하는 2-step 구조입니다. 같은 캐릭터를 반복 조회할 때마다 OCID 변환 API가 추가 호출되는 문제를 ConcurrentHashMap 기반 인메모리 캐시로 해결했습니다. OCID는 캐릭터가 유지되는 한 불변이므로 TTL 없이 영구 보관하며, 동시 요청에도 thread-safe하게 동작합니다.

ConcurrentHashMap 캐시 2-step OCID 조회 Thread-safe
02

장비 슬롯 이름 정규화 — 그리드 매핑

Nexon API가 반환하는 장비 슬롯 이름에는 숫자 suffix, 괄호, 공백 등이 혼재합니다 (예: "반지1", "반지 (1)", "귀고리"). 고정된 장비 슬롯 그리드에 정확히 매핑하려면 정규화 함수가 필수였습니다. 슬롯 이름에서 숫자·괄호·공백을 제거한 뒤 슬롯 인덱스로 순서를 제어하는 방식으로 해결했습니다.

슬롯 이름 정규화 그리드 레이아웃
03

유니온 블록 좌표 시각화

유니온 레이더 API는 각 블록의 좌표 배열과 블록 모양 정보를 반환합니다. 게임 내 맵과 동일하게 보이도록 좌표 기준점을 맞추고, 블록별 직업 색상과 모양을 캔버스에 렌더링했습니다. API 좌표 체계와 화면 픽셀 좌표 간 변환 로직을 별도로 설계해야 했습니다.

좌표 변환 Canvas 렌더링
04

외부 API 장애 영향 최소화

캐릭터 조회 시 외부 API 장애가 발생하면 서비스 전체가 영향을 받는 구조였습니다. 각 API 호출을 독립적으로 분리하고, 실패한 항목만 개별 재시도할 수 있도록 프론트엔드에 retry 버튼을 제공했습니다. 백엔드에서는 전역 예외 핸들러로 Rate Limit(429)와 일반 장애를 구분해 클라이언트에 명확한 에러 메시지를 전달합니다.

개별 재시도 (retry) 전역 예외 핸들러 Rate Limit 처리
06 · Retrospective

배운 점 · 회고

🤝

역할 분담과 인터페이스 설계

API 연동처럼 명확히 분리 가능한 영역을 팀원에게 위임하고, 팀원이 만든 REST API를 프론트에서 그대로 소비하는 경험을 통해 인터페이스 중심 협업을 익혔습니다.

⚛️

React 컴포넌트 설계

커스텀 훅(useCharacterData, useSearchHistory)으로 상태 로직을 분리하고, 컴포넌트를 기능 단위로 쪼개는 구조를 직접 설계하며 유지보수성을 높이는 방법을 배웠습니다.

🗂️

외부 API 데이터 구조 대응

Nexon API가 반환하는 복잡한 중첩 DTO 구조를 파싱하고 UI에 맞게 가공하면서, 외부 데이터를 내부 표현으로 변환하는 레이어의 중요성을 체감했습니다.

🖥️

Electron 데스크탑 앱

React 앱을 Electron으로 감싸 데스크탑 앱을 만드는 과정에서 웹과 네이티브 환경의 차이, 빌드·패키징 파이프라인을 경험했습니다.

📐

개선할 점

현재 서버를 띄워야만 동작하는 구조입니다. 백엔드를 클라우드에 배포하고, 웹 버전으로도 접근 가능하도록 개선할 계획입니다.

🔁

에러 복원력 설계

API 일부가 실패해도 나머지 데이터를 정상 표시하고, 실패한 부분만 재시도할 수 있는 구조를 설계하며 사용자 경험 중심의 에러 처리를 고민하게 됐습니다.
