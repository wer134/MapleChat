01 · Overview

프로젝트 개요

PROJECT DESCRIPTION

MapleChat은 메이플스토리 Open API를 활용해 캐릭터·길드·유니온 정보를 조회·시각화하는 웹앱입니다. 캐릭터 이름 하나로 장비·스탯·유니온 배치를 한 화면에서 확인하고, WebSocket 기반 실시간 채팅과 캐릭터 비교 기능을 제공합니다. Spring Boot REST API가 Nexon Open API의 프록시 역할을 하고, React 프론트엔드가 데이터를 시각화합니다. Vercel(프론트) + Railway(백엔드)로 배포되어 누구나 브라우저에서 바로 사용할 수 있으며, Electron 데스크탑 앱 빌드도 지원합니다.

05 · Challenges

기술적 도전과 해결

01

Nexon API 2-step 구조 — OCID 인메모리 캐시 (팀원 구현)

넥슨 API는 이름으로 직접 조회가 불가능하고, 이름 → OCID → 상세 정보 순서의 2-step 구조입니다. 같은 캐릭터를 반복 조회할 때마다 OCID 변환 API가 추가 호출되는 문제를 ConcurrentHashMap 기반 인메모리 캐시로 해결했습니다. OCID는 캐릭터가 유지되는 한 불변이므로 TTL 없이 영구 보관하며, 동시 요청에도 thread-safe하게 동작합니다.

ConcurrentHashMap 2-step OCID 조회 Thread-safe
02

장비 슬롯 이름 정규화 — 그리드 매핑

Nexon API가 반환하는 장비 슬롯 이름에는 숫자 suffix, 괄호, 공백이 혼재합니다 (예: "반지1", "반지 (1)", "귀고리"). 고정된 장비 그리드에 정확히 매핑하려면 정규화 함수가 필수였습니다. 슬롯 이름에서 숫자·괄호·공백을 제거한 뒤 슬롯 인덱스로 순서를 제어하는 방식으로 해결했습니다.

슬롯 이름 정규화 그리드 레이아웃
03

유니온 블록 좌표 → 화면 픽셀 변환

유니온 레이더 API는 블록별 좌표 배열과 모양 정보를 반환합니다. 게임 내 맵과 동일하게 보이도록 API 좌표 체계와 화면 픽셀 좌표 간 변환 로직을 별도로 설계하고, 직업군별 색상과 블록 모양을 올바른 위치에 렌더링했습니다.

좌표 변환 블록 렌더링
04

병렬 API 호출 + 독립 에러 처리

캐릭터 조회 시 장비·스탯·어빌리티·성향·하이퍼스탯을 Promise.all로 동시에 요청합니다. 각 항목이 개별 에러 상태를 가지므로 일부 API 실패가 전체 화면 오류로 번지지 않으며, 항목별 재시도 버튼을 제공합니다. 백엔드에서는 전역 예외 핸들러로 Rate Limit(429)와 일반 장애를 구분해 클라이언트에 명확한 에러 메시지를 전달합니다.

Promise.all 병렬 호출 항목별 재시도 Rate Limit 처리
05

Vercel + Railway 배포 · CORS 설정

프론트(Vercel)와 백엔드(Railway)가 서로 다른 도메인에 있어 브라우저의 CORS 정책이 요청을 차단했습니다. Spring Boot CORS 설정에서 CORS_ALLOWED_ORIGINS 환경변수로 허용 도메인을 동적으로 주입하고, Vercel에는 REACT_APP_API_URL을 설정해 올바른 엔드포인트로 요청이 가도록 구성했습니다.

CORS 설정 환경변수 분리 Vercel · Railway 배포
06 · Retrospective

배운 점 · 회고

🤝

인터페이스 중심 협업

API 연동처럼 명확히 분리 가능한 영역을 위임하고, 팀원이 만든 REST API를 프론트에서 그대로 소비하며 인터페이스 기준의 협업 방식을 익혔습니다.

⚛️

React 컴포넌트·훅 설계

커스텀 훅(useCharacterData, useSearchHistory, useChat)으로 상태 로직을 분리하고, 컴포넌트를 기능 단위로 쪼개는 구조를 직접 설계하며 유지보수성을 높이는 방법을 배웠습니다.

🔌

WebSocket 실시간 통신

STOMP over SockJS로 Spring Boot WebSocket 서버와 React 클라이언트를 연결하는 과정에서 실시간 통신 프로토콜과 구독/발행 패턴을 직접 구현했습니다.

☁️

클라우드 배포 · 환경 분리

Vercel + Railway 배포 환경에서 CORS, 환경변수, 빌드 설정을 분리·관리하며, 로컬과 프로덕션 환경의 차이를 다루는 실전 경험을 쌓았습니다.

🗂️

외부 API 데이터 대응

Nexon API가 반환하는 복잡한 중첩 DTO와 일관성 없는 필드명을 파싱·정규화하면서, 외부 데이터를 내부 표현으로 변환하는 레이어의 중요성을 체감했습니다.

🔁

에러 복원력 설계

API 일부 실패 시에도 나머지 데이터를 정상 표시하고, 실패 항목만 재시도하는 구조를 설계하며 사용자 경험 중심의 에러 처리 방법을 고민하게 됐습니다.
